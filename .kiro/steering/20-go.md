# Go rules (Go 1.27)

## Layout and naming
- MUST: binaries in `cmd/<name>/main.go`; everything else in `internal/`. `main` only wires config, dependencies and `run()`.
- MUST: short, specific package names (`placement`, `oauth`, `sqlsafety`). Never `util`, `common`, `misc`, `helpers`, `types`. Names don't stutter (`cell.Spec`, not `cell.CellSpec`); initialisms keep case (`ID`, `URL`, `SNI`).

## Errors
- MUST: check every error. Wrap with context: `fmt.Errorf("placement: decide for %s: %w", ref, err)`. No "failed to" prefixes.
- MUST: errors callers match are exported sentinels (`var ErrNoCapacity = errors.New("placement: no capacity")`) or typed errors; match with `errors.Is/As`.
- MUST: handle an error once: return it or log it, not both.
- MUST: no `panic` outside `main` initialization; never let a panic cross a package boundary. HTTP/job middleware recovers, logs with stack, and returns 500 / fails the job.

## Context and concurrency
- MUST: `ctx context.Context` is the first parameter of every function that does I/O or can block; never stored in structs; never nil (use `context.TODO()` only in tests).
- MUST: every `context.WithTimeout/WithCancel/WithDeadline` has its `cancel` called (`defer cancel()`); `go vet` and gosec G118 must stay clean.
- MUST: every goroutine has a documented owner and exit condition; the owner waits for it (`errgroup`, `sync.WaitGroup.Go`). No fire-and-forget.
- MUST: bound fan-out with `errgroup.SetLimit`. Channels are unbuffered or size 1 unless a comment justifies the size.
- MUST: shared state is protected by a mutex or owned by one goroutine; `go test -race` runs in CI and covers the concurrent paths.
- SHOULD: expose synchronous APIs; let callers add concurrency.
- Note: GOMAXPROCS follows the container CPU limit since Go 1.25; don't add `automaxprocs`.

## Design
- MUST: accept interfaces, return concrete types. Interfaces are defined by the consumer package.
- MUST: no mutable package-level state and no `init()` side effects. Dependencies are passed explicitly (constructor or struct fields).
- MUST: `defer` releases locks, rows (`rows.Close()`), transactions (`tx.Rollback` after commit is a no-op), response bodies and files.
- MUST: config is read once from environment variables into a typed struct, validated at startup, and passed down. Invalid config fails fast with a message that says how to fix it.
- MUST: logging via `log/slog` (JSON handler, redacting `ReplaceAttr`), never `fmt.Print*` or the `log` package in services.
- SHOULD: make zero values useful; start enums at `iota + 1`; assert interface compliance with `var _ Adapter = (*OCIAdapter)(nil)`.

## Database (pgx v5 + sqlc + River, Supabase through Supavisor)
- MUST: one `pgxpool.Pool` per process with an explicit `MaxConns` from the budget in `plan/01-architecture.md` §10.2, `MaxConnLifetime` set, and a `statement_timeout` for the role.
- MUST: pools on the transaction pooler (port 6543) set `DefaultQueryExecMode = pgx.QueryExecModeExec` and don't use `SendBatch`/pipelining, session settings, advisory session locks, `LISTEN` or temp tables. Only the River coordinator, River UI, migrations and dumps use the session pooler (5432).
- MUST: queries only via sqlc; transactions via a helper that always rolls back on error; River jobs inserted with `InsertTx` in the same transaction as the state change.
- MUST: River workers are idempotent: re-running a job after a crash produces the same result. Each job kind sets its own timeout.

## HTTP servers and clients
- MUST: servers set `ReadHeaderTimeout` (gosec G112), `ReadTimeout`, `WriteTimeout` (streaming MCP handlers use per-write deadlines instead), `IdleTimeout` and `MaxHeaderBytes`; bodies are wrapped in `http.MaxBytesReader`. Never use the timeout-less `http.ListenAndServe` helpers (G114).
- MUST: clients set `Timeout`, use one shared `http.Transport` with bounded idle connections, always close `resp.Body`, and read bodies through `io.LimitReader`.
- MUST: handlers are generated from OpenAPI (oapi-codegen strict server); authorization happens in the handler before any object load returns data.
- MUST: cookies (if any) set `Secure`, `HttpOnly` and `SameSite` (G124). Redirects never forward `Authorization` to another host (G119).
- MUST: `net/http/pprof` is never registered on a public listener (G108).

## Security (gosec runs in golangci-lint; findings fail CI)
- MUST: random tokens and keys from `crypto/rand` (`rand.Text()` for ≥ 128-bit tokens); `math/rand` only for jitter and tests (G404).
- MUST: no SQL built with `fmt.Sprintf` or string concatenation (G201/G202/G701); the MCP executor's parsed SQL is the documented exception.
- MUST: integer conversions that can overflow are checked (G115); parse with `strconv.ParseInt(s, 10, bitSize)` into the target size (G109).
- MUST: TLS configs never set `InsecureSkipVerify` and keep `MinVersion: tls.VersionTLS12` (G402); no MD5/SHA-1/DES/RC4 (G401/G405, G501–G505).
- MUST: decompression and archive reads are bounded (`io.CopyN`, G110); file paths from input are rejected, not cleaned (G304/G305).
- MUST: outbound fetches of user-controlled URLs use `internal/platform`'s SSRF-guarded client (G704).
- MUST: HTML is produced only with `html/template`; `text/template` never renders untrusted data into HTML (G203/G708).
- MUST: suppressions are `// #nosec G### -- reason` and CI runs gosec with `-nosec-require-rules -nosec-require-justification`.
- MUST: `govulncheck ./...` passes; the Go toolchain stays on the latest patch release.

## Testing
- MUST: table-driven tests with messages in the form `Decide(%v) = %v; want %v`; `go test -race` in CI.
- MUST: integration tests use the local Supabase stack or testcontainers, through a pooler in the same mode production uses; operator tests use envtest.
- MUST: native fuzzing for parsers (`func FuzzParseStartup(f *testing.F)`), run for a bounded time in CI.
