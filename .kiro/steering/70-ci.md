# CI rules (GitHub Actions on the Free plan)

## Supply chain and permissions
- MUST: every `uses:` pins a full commit SHA from the upstream repository (with the version in a trailing comment); the organization's Actions policy allows only SHA-pinned actions where the plan offers it, and `zizmor` enforces it otherwise; Renovate updates the pins.
- MUST: top-level `permissions: contents: read`; each job raises only what it needs (`packages: write`, `id-token: write` for keyless signing).
- MUST: `actions/checkout` uses `persist-credentials: false`.
- MUST: no `pull_request_target` or `workflow_run` triggers that check out or run PR code; artifacts from other workflows are treated as untrusted.
- MUST: `${{ github.event.* }}` and other attacker-controllable values never appear directly in `run:`; pass them through `env:` and quote the variable.
- MUST: GitHub Free doesn't offer deployment environments, branch rules or CODEOWNERS enforcement on private repos. Until the move to GitHub Team: deploy, wrangler and `terraform apply` workflows run only on `workflow_dispatch` (only users with write access can trigger it, and the owner is the only one until the Team upgrade), read only the secrets they need, and never run on `pull_request`; build and test workflows get no deploy secrets.
- MUST: no structured (JSON) secrets; values derived from secrets are masked with `::add-mask::`.
- MUST: cloud access from CI uses OIDC or short-lived scoped tokens where the provider supports it; long-lived keys are scoped to one purpose and rotated.
- MUST: `CODEOWNERS` lists the owner for `.github/workflows/` (advisory on Free, enforced after the Team upgrade); Actions may not create or approve pull requests.
- MUST: Trivy's secret scanner runs on every push.
- MUST: `actionlint` and `zizmor` run on every change to `.github/`.

## Cost and speed (2,000 free minutes/month)
- MUST: path filters: a job runs only when its component, its shared dependencies or the workflow itself changes.
- MUST: caches for Go modules/build, Cargo (`target` + registry) and pnpm store; concurrency groups cancel superseded runs on the same branch.
- MUST: arm64 images build natively on `ubuntu-24.04-arm`, amd64 on `ubuntu-24.04`; no QEMU emulation.
- MUST: every job has `timeout-minutes`.
- MUST: the Actions budget stays at US$0 with "stop usage" on. Heavy k3d e2e suites may run on a self-hosted runner in WSL2 (private repository only, ephemeral workspace, no production credentials).

## Pipeline content
- MUST: lint → test → build → scan → sign, failing fast: gofmt/golangci-lint (gosec), `go test -race`, govulncheck; cargo fmt/clippy/nextest/deny/audit; ESLint/tsc/Vitest, `next build --webpack` static export + CSP hash check, Playwright + axe; hadolint; ShellCheck; `terraform fmt/validate` + Trivy config; kubeconform; Trivy image and lockfile scans; syft SBOM; cosign keyless signing on `main`.
- MUST: release images are pushed to ghcr.io (private, `packages: write` only in the build job) by digest and the digest is written back to the Flux manifests by a PR, never pushed straight to `main`.
- MUST: CI never connects to Supabase, the K3s API or the VMs (plan/01 §10.2); Flux pulls from git.
- MUST: a K3s version bump runs the conformance and CNPG smoke suites on k3d before the system-upgrade-controller Plan changes.
